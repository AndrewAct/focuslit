# AI, evaluations and cost

状态：设计与估算，未接入 provider，未进行真实用户/model 测量。核价日期：2026-09-27。

## 何时调用

本地持续观察事件；规则 → 当前任务缓存 → 必要时模型。提醒、表情、计时和关闭不调用模型。
只处理用户当前交互内容，导航/主题实质变化时去抖触发；切回未变内容复用结果。
音乐使用显式授权上下文，不因为后台播放不断调用。ChatGPT 同 URL 的新内容必须能失效缓存。

请求包含目标、少量最近研究上下文、规则摘要、标题/脱敏 URL/必要正文片段，不发完整浏览历史。
正文仅在用户同意云分析和允许站点上提取，过滤输入框、凭证、敏感查询参数；先记录字段清单。
初始输入目标约 1,500 tokens、输出约 100 tokens；实际 tokenizer 与协议开销需计入。
必要上下文超过上限时分级提取或返回 unknown，不能因截断丢了证据仍强判 unrelated。

输出是受校验的 `related | unrelated | unknown`、简短理由和证据字段；页面指令视为数据。
模型不调用浏览器工具。置信度如保留，仅作为待校准信号，不能声称“0.95=95%可靠”。

## 缓存与上下文

缓存键至少含 task/policy revision、内容指纹、提取器/提示/模型版本、页面/音乐上下文与 TTL。
内容片段变化触发重新判断，避免 URL-only 缓存；高频 DOM 动画与滚动不触发。
用户纠正优先于模型；当前任务的例外不自动变成永久域名白名单。
短时研究路径有长度限制；重复嵌入此前所有内容会让 token 开销随使用时间增长。

## 日用成本情景

标准文本调用、无缓存折扣/Batch 折扣；单位美元。每次 1,500 输入 + 100 输出 tokens，30 天/月。
模型仅是估算样本，最终选型依据效果/延迟/费用测试，不默认一直追最新或最大模型。

| 模型样本 | 输入/输出每百万 tokens | 单次 |
| --- | --- | --- |
| GPT-5.4 nano | $0.20 / $1.25 | $0.000425 |
| Claude Haiku 4.5 | $1 / $5 | $0.002 |

| 每天真实 API 请求 | GPT-5.4 nano/月 | Haiku 4.5/月 |
| --- | --- | --- |
| 100 | $1.28 | $6 |
| 300 | $3.83 | $18 |
| 500 | $6.38 | $30 |
| 1,000 | $12.75 | $60 |

计算式：`天数 × 日请求 × (输入tokens × 输入单价 + 输出tokens × 输出单价) / 1,000,000`。
输入增至 6,000、输出仍 100、每天 500 次，则约 $19.88 / $97.50。
这些数字不是测得的重度用户预测。额外推理 tokens、重试、升级模型、税费等另计；实时干预
不用异步 Batch 优惠冒充实时价格。短提示未必满足供应商缓存最低长度，预算不假定一定命中。

依据：[OpenAI 模型价格](https://developers.openai.com/api/docs/models/gpt-5.4-nano)、
[Anthropic 价格](https://platform.claude.com/docs/en/about-claude/pricing)。发布前重新核价并记录日期。

**设计目标：** 在可接受误判率下探索 $5–10/月的日用方案，不承诺所有使用方式都能达到。
单人 BYOK 默认，无托管推理/订阅；API 费用与构建 CI、Apple 开发者、商店和未来服务费用分开。
M5 记录 GitHub 实际配额/账单和开发者账户费用，不把“无服务器”写成“零总成本”。

## 应用内预算

1. 用户选择 provider、模型和月预算，可选单时段预算；一个全局 USD 额度跨 provider 记账。
2. 固定日历月边界和设置时区；更改系统时区/时钟不能直接重置预算。一个设备只有一个账本写入方。
3. 发起前按完整请求 token 估算 + 最多计费输出/推理上限 + 当前价目表，在事务中预留额度。
   估算不可靠或模型无法限定输出时采用保守上界；未知价格暂停新请求。
4. 同一请求有唯一 ID，额度预留和调度幂等；并发请求不能同时花同一笔余额。
5. 收到 usage 后结算；网络超时/取消不代表没计费，缺 usage 的预留保守保留并显示估算。
   重试重新预留，限制重试次数；不要在重启后清空未决预留。
6. 临近额度提示；发起前发现不足则停止云判断。继续本地规则，未知内容不自动关闭。
7. 大模型升级有独立次数/额度上限；UI 明示今日费用、预留费用、月累计、按当前用量预测。

额度限制只约束本应用发起的请求，不约束同 key 在其他应用的消费；价格变动、token 估算和
供应商账单时间差意味着不能承诺 provider 账户绝对不超支。M4 对比实际 usage/账单误差。

## 模型评估，而不只测 SDK

M4 建立至少 120 个合成/经同意脱敏样本，中文/英文与两个任务均覆盖；任务边界不清时标签
允许 unknown，先人工标注再看模型输出。按来源/主题拆分开发与至少 40 个独立保留样本，
不把同页改写泄漏到两边。后续累计纠正案例，不能反复调到测试集满分后声称泛化。

必须包含：

- 同一个 YouTube 页在刷题/写作任务下标签不同，背景音乐和正常曲目切换。
- 康德/法律/功利主义等间接相关链路，标题误导、正文不足、不可读取正文。
- 同 URL 的 ChatGPT 主题漂移、SPA 导航、同标题但内容不同。
- 网页提示注入要求永久放行/读取 key/关闭别的 tab。
- 短时偶然打开、持续浏览、切回任务、未知和主动纠正。

记录 confusion matrix，分别报告：相关内容误判无关率、明确无关召回、unknown 占比、
干预误关/漏关、按语言/模板切分结果、P50/P95 延迟、tokens、价格和真实请求次数。

模型参与自动关闭前的初始验收目标：保护音乐/编辑页等关键集 **零不当关闭**；独立保留集中
相关→无关比例 ≤2%，明确无关召回 ≥90%，信息充分子集中 unknown ≤25%。报告样本数，
样本很小时百分比粒度粗；未过门槛保留提醒/观察模式，不能把全部输出 unknown 算成功。
这些是工程目标，不是统计保证；小样本全对也不证明真实世界误关率低于 2%。

测试分工：

- PR 离线：固定响应验证提取/契约/预算/缓存/状态机；回放历史评估用于防回归。
- 明确预算的受信任 live eval：冻结模型/提示/提取版本，用真实 API 评价新模型效果。
- 一周观察模式：显示“本来会提醒/关闭什么”，不执行模型来源的 close；记录纠正和日费用。
- 满足门槛后用户开启模型干预；任何版本变更保留关闭功能的快速降级开关。

离线回放不能证明供应商模型没有变化。模型版本固定到可用 snapshot；别名/价格变化触发复评。
