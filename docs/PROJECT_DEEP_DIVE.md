## 功能、价值与范围

问题：同一网站对当前任务可能有帮助，也可能导致持续分心；传统域名拦截无法表达这种区别。
目标：用户指定任务，助手在尊重资料、音乐、阅读和休息的前提下执行可预测的干预。
当前行为：仓库只有规划与 PR 模板；所有产品能力未实现。
范围：一台 macOS、Safari+Chrome、一个猫咪角色、中英文、可选云分类。无分布式系统需求。

## 关键决策记录

| 决策 | 理由 | 接受的代价 | 什么证据会改变它 |
| --- | --- | --- | --- |
| TS/Electron + 少量 Swift | 符合语言偏好，UI/扩展复用，原生边界明确 | 包大小/内存和双工具链 | M1 集成不可行或资源长期不达标 |
| 功能核心本地确定性 | 可测试、离线可用，模型故障不接管执行 | 更多显式状态和协议 | 不用模糊“更智能”作为推翻理由 |
| 规则/缓存后再请求模型 | 成本和隐私可控 | 提取/缓存失效复杂 | 真实误判或缓存收益不足 |
| provider 可替换，用户二选一 | 适配不同成本/偏好 | 两个契约适配器维护 | 不是两个模型每次投票 |
| 先做一个猫咪 | 让表情、文案、动作保持一致 | 暂无角色个性化 | 已验证长期使用体验后再扩展 |
| 开发阶段就验证签名安装 | Safari/host 路径风险必须早暴露 | M1 多一些打包工作 | 无证书只影响签名子门槛，不阻断所有独立实现 |

## 成功指标及限制

- 用户是否更容易回到当前任务；提示到返回的时间是 proxy，不能测量心理专注。
- 用户标记误拦/误关次数与具体原因；固定测试集零事故不等于真实世界零风险。
- 每小时提示数、主动隐藏次数、长时体验反馈；更多拦截不等于更好产品。
- 每活动小时费用、日/月请求分布、输入长度、P50/P95 延迟和本地资源。
- 每个支持平台的安装/恢复成功证据；能编译不等于已支持。
